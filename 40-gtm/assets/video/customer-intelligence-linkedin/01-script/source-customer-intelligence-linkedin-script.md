# Customer Intelligence — LinkedIn Script
**Audience:** LinkedIn feed — founders, product leads, consultants (the wedge ICP, not the full operator/EOS audience)
**Format:** 1080×1080 square, 30fps. Talking head (real) + product footage (real) + one animated beat.
**Target length:** ~50s after crossfades
**Companion doc:** `30-strategy/messaging-house-customer-intelligence.md` — this script is the video expression of that wedge, not the fuller operating-system vision.

---

## Visual philosophy (read before shooting or animating anything)

**Default to real.** This video's entire argument is "trust the evidence, not an AI's word for it" — so the video itself has to earn that same trust. Wherever a scene claims a real UpSight capability, show the real thing: a real screen, a real recording, a real drill-down. A stock icon or illustration standing in for a real feature undercuts the video's own point.

**The one exception is Scene 2** (the objection beat) — there's no real UpSight screen to show for "everyone's guessing, or trusting an AI that might be making things up," because that's the world *before* UpSight, not a UpSight feature. That's the one scene built as a Remotion animation (kinetic type + a glitch/corruption effect on AI-generated-looking text) — and the glitch effect isn't just filler, it visually enacts the claim being made.

Everywhere else, Remotion's job is to **frame and reveal real assets** — grow+dissolve reveals, browser-chrome framing on screenshots, quote-highlight overlays on the real evidence clip — not to invent graphics standing in for things that should be proven on screen.

| Scene | Visual type | Why |
|---|---|---|
| 0 — Hook | **Real footage** (talking head) | Personal credibility is the whole point of the open |
| 1 — Capture montage | **Real footage/screenshots** ×4 | Proving real channels exist — faking this defeats the claim |
| 2 — Problem/objection | **Remotion animation** (kinetic type + glitch) | No real UpSight screen represents "the world before UpSight" |
| 3 — Evidence (money shot) | **Real footage** (recorded interview clip) | This is the scene that defeats "AI could be lying" — must be real |
| 4 — Decisions payoff | **Real screenshot** (drill-down/matrix view) | Proving a real analysis capability |
| 5 — Close | **Real footage** (talking head) | Bookends scene 0 |

## Pre-Recording / Pre-Capture Checklist

- [ ] Talking-head session: Scenes 0 + 5 recorded together, same setup, same take energy (they need to feel like one sitting)
- [ ] Call recording view — clean project, no test/placeholder data visible
- [ ] Survey view — a real survey in progress, not an empty draft
- [ ] AI Interviewer — a real session mid-conversation, not a static empty state
- [ ] Event Kiosk — either a live capture at an actual event, or a clean screen-capture of the kiosk UI if no live event is coming up soon
- [ ] Evidence clip (Scene 3) — pick a real interview with 2–3 strong, clearly-attributable quotes on ONE theme; this is the scene that has to hold up under scrutiny, choose carefully
- [ ] Decisions payoff (Scene 4) — a project with enough data that the drill-down view actually looks substantive, not sparse

## Risk / Contingency

| Risk | Mitigation |
|---|---|
| No live event before this needs to ship | Screen-capture the Event Kiosk UI cleanly instead of live footage; note it's a UI capture, not a "the video" moment |
| Evidence clip (Scene 3) doesn't have a clean 2–3 quote moment | Don't force it — find a different interview/theme pair that does. This scene is not worth compromising on. |
| Talking-head takes feel flat | Record 3–4 takes of the hook line; the personal-story energy is the whole differentiator of this open |
| Glitch effect (Scene 2) reads as gimmicky in review | Fall back to plain kinetic type with no glitch, just bold sequential text builds — still real-vs-fake footage everywhere else carries the argument |

## Voiceover Notes

- Continuous narration — Rick's voice carries the whole video, not just the talking-head bookends. On-screen text in scenes 1–4 is reinforcement, not the primary information.
- Natural conversational pace (~2.5 words/sec), not a "read the slide" pace — this should sound like Rick talking, not narrating copy.
- Don't explain the UI in the VO — the visuals show the feature; the VO carries the argument (why it matters).
- The line to protect above all others: *"you can trace every one straight back to the actual conversation."* That's the sentence the whole video is built to earn.
