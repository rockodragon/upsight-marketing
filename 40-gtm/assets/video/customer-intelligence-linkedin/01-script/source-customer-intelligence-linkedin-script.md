# Customer Intelligence — LinkedIn Script
**Audience:** LinkedIn feed — founders, product leads, consultants (the wedge ICP, not the full operator/EOS audience)
**Format:** 1080×1080 square, 30fps. Talking head (real) + product footage (real). No animated scenes as of this revision.
**Target length:** ~63s after crossfades (up from an earlier ~50s target — see "Runtime note" below)
**Companion doc:** `30-strategy/messaging-house-customer-intelligence.md` — this script is the video expression of that wedge, not the fuller operating-system vision.

---

## Visual philosophy (read before shooting anything)

**Default to real.** This video's entire argument is "trust the evidence, not an AI's word for it" — so the video itself has to earn that same trust. Wherever a scene claims a real UpSight capability, show the real thing: a real screen, a real recording, a real drill-down. A stock icon or illustration standing in for a real feature undercuts the video's own point.

**Revision note:** an earlier draft of this script had one animated scene (a kinetic-type/glitch beat for the "AI might be hallucinating" objection). Folding that objection into the evidence scene — raise it and answer it in the same breath, right before the real proof clip — removed the need for it. There is no longer a scene without a real screen behind it. Remotion's job throughout is to **frame and reveal real assets** (crossfades, browser-chrome framing, quote-highlight overlays on the real evidence clip) — not to invent graphics standing in for things that should be proven on screen.

| Scene | Visual type | Why |
|---|---|---|
| 0 — Hook | **Real footage** (talking head) | Leads with an observation the audience recognizes (a pattern *you noticed*, not a challenge you aim at them), then a credibility bridge, then the product — not a bio-first open, and deliberately not an influencer-style gotcha |
| 1 — Capture montage | **Real footage/screenshots** ×4 | Proving real channels exist — faking this defeats the claim |
| 2 — Evidence (objection + proof, combined) | **Real footage** (recorded interview clip) | The "AI could be lying" objection is named and defeated in one breath — must be real |
| 3 — Decisions payoff | **Real screenshot** (drill-down/matrix view) | Proving a real analysis capability |
| 4 — Close | **Real footage** (talking head) | Bookends scene 0 |

I'd cut (a) before (b) — the objection-then-proof beat in Scene 2 is the sentence this whole video is built to earn; don't thin that one out first. **Do not cut the opening observation to save time** — that's the thumb-stop; losing it costs you the whole video.

## Pre-Recording / Pre-Capture Checklist

- [ ] Talking-head session: Scenes 0 + 4 recorded together, same setup, same take energy (they need to feel like one sitting)
- [ ] Hook take (Scene 0) — record 3–4 full takes of the ~25s continuous line; this is the longest single ask of the whole shoot, get it natural, not recited
- [ ] Call recording view — clean project, no test/placeholder data visible
- [ ] Survey view — a real survey in progress, not an empty draft
- [ ] AI Interviewer — a real session mid-conversation, not a static empty state
- [ ] Event Kiosk — either a live capture at an actual event, or a clean screen-capture of the kiosk UI if no live event is coming up soon
- [ ] Evidence clip (Scene 2) — pick a real interview with 2–3 strong, clearly-attributable quotes on ONE theme; this is the scene that has to hold up under scrutiny, choose carefully
- [ ] Decisions payoff (Scene 3) — a project with enough data that the drill-down view actually looks substantive, not sparse

## Risk / Contingency

| Risk | Mitigation |
|---|---|
| No live event before this needs to ship | Screen-capture the Event Kiosk UI cleanly instead of live footage; note it's a UI capture, not a "the video" moment |
| Evidence clip (Scene 2) doesn't have a clean 2–3 quote moment | Don't force it — find a different interview/theme pair that does. This scene is not worth compromising on. |
| 25s hook feels long / loses energy partway through | Split into 2 natural jump-cuts of the same take (common in creator content) rather than forcing the words shorter — pacing fix, not a content fix |
| Total runtime (~63s) feels too long in review | Trim per the Runtime note above — the hook's middle sentence first, not the evidence scene |

## Voiceover Notes

- Continuous narration — Rick's voice carries the whole video, not just the talking-head bookends. On-screen text in scenes 1–3 is reinforcement, not the primary information.
- Natural conversational pace, not a "read the slide" pace — this should sound like Rick talking, not narrating copy. The hook especially should NOT sound rehearsed.
- Don't explain the UI in the VO — the visuals show the feature; the VO carries the argument (why it matters).
- The line to protect above all others: *"you can trace every one straight back to the actual conversation."* That's the sentence the whole video is built to earn.
